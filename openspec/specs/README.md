# Project Specifications

Living specifications that describe what this project does.

Specs are written in plain Markdown with concrete scenarios. They are the source of truth for project behavior.

## Format

```markdown
## Requirement: <Name>
<Description of what the system SHALL do>

### Scenario: <Scenario name>
- **WHEN** <trigger condition>
- **THEN** <expected outcome>
```

## Guidelines

- Each spec file covers a cohesive feature area
- Requirements use SHALL/MUST for mandatory, SHOULD for recommended, MAY for optional
- Scenarios are concrete and testable
- Specs are updated as changes are archived
